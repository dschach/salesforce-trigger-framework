      Reject a null handler type.

      Main method, called from the trigger. It dispatches to the context method and then to andFinally().
      See the sample trigger for the best way to set up your handler.
      The switch names all 7 trigger operations, and validateRun() rejects a null operation, so SwitchWithoutWhenElse is suppressed for this method.
    • setBypass (handlerName, desiredValue)
      Set bypass status to a specific value. Eliminates the need to know the current bypass status.
      false also clears the global bypass, so that this handler runs. Every other handler then runs too, because a global bypass cannot exclude 1 handler.
      So the save-and-restore idiom below restores the named bypass only, not a global bypass that was active before.
    • setMaxLoopCount (max)
      Limit the number of times run() executes this handler's context methods.
      The count is kept per handler name for the whole transaction, and it starts when this method is first called for the handler. Every trigger context and every 200-record chunk counts as 1 run. A bypassed run is not counted, and a run that the limit stops is counted.
      When the limit is exceeded, run() logs a warning and returns without calling the context method or andFinally().
      Returning TriggerHandler enables method chaining when used in a trigger.
    • setTestContext (operation)
      Make this handler run as if a trigger fired the given operation, so that a test can call run() without DML.
      Set the records that the handler reads before you call run(), for example through @TestVisible fields of the handler.
      Outside a test it changes nothing: the handler keeps the context of the real trigger.
    • setTriggerContext ()
      Set the current context from Trigger.operationType. Called by both constructors.
    • setTriggerContext (opType, testMode)
      Set the current trigger context from a System.TriggerOperation.
      Outside a trigger, and in a test that does not force a context, isTriggerExecuting is false.
    • showDebug ()
      Turn on the entry and exit debug output for every handler that runs later in the transaction.
      Use this in the trigger or handler.
    • showDebug (enabled)
      Turn the entry and exit debug output on or off for every handler that runs later in the transaction.
    • showLimits ()
      Turn on the limits debug output for every handler that runs later in the transaction.
      Use this in the trigger or handler.
    • showLimits (enabled)
      Turn the limits debug output on or off for every handler that runs later in the transaction.
      Use this in the trigger or handler.
    • validateRun ()
      Decide whether this run continues.
      false makes run() return before the context method.
